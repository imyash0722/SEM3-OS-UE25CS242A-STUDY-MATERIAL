Topic 14: Signals & Signal Handling¶

Source: Lecture 13 (Unit 2) + Textbook Ch. 11

14.1 Signal Fundamentals¶

Definition¶

A signal is a software interrupt mechanism used in UNIX-like systems to notify a process/thread that a specific asynchronous or synchronous event has occurred.

Universal Signal Lifecycle¶

  1. Generation — Hardware exception, kernel event, timer, or user action triggers signal
  2. Delivery — Kernel marks signal as pending, delivers to target process/thread
  3. Handling — Process executes designated action (default or user-defined handler)

14.2 Signal Classification¶

Synchronous Signals¶

Generated by internal operation of running program. - Delivered to the identical thread whose instruction triggered the event - Examples: - SIGSEGV — Illegal memory access - SIGFPE — Integer division by zero - SIGILL — Illegal machine instruction

Asynchronous Signals¶

Generated by external event. - Delivered to process or any thread capable of receiving it - Examples: - SIGINT — User presses <Ctrl>+<C> - SIGALRM — Timer expiration - SIGCHLD — Child process termination - Explicit kill() from another process

14.3 Signal Handlers¶

Two Types¶

Type Description
Default Handler Kernel-provided; actions: Terminate, Core Dump, Ignore, Stop, Continue
User-Defined Handler Custom C function registered via signal() or sigaction()

Non-Catchable Signals (Critical!)¶

Signal Number Description
SIGKILL 9 Forceful termination — uncatchable, unignorable
SIGSTOP 17/19/23 Forceful suspension — uncatchable, unignorable

14.4 Signal Handling in Multithreaded Programs¶

The Delivery Problem¶

  • Single-threaded: unambiguous delivery to process
  • Multithreaded: which thread receives the signal?

Four Delivery Strategies¶

  1. Thread-specific — Mandatory for synchronous exceptions (SIGSEGV, SIGFPE)
  2. All threads — Process termination signals (SIGINT)
  3. Non-blocked threads — Deliver to first thread not blocking the signal
  4. Dedicated signal thread — Use sigwait() to handle all signals

Signal APIs¶

// Process-targeted
#include <signal.h>
int kill(pid_t pid, int signal);
// Kernel decides which non-blocking thread receives it

// Thread-targeted (POSIX Pthreads)
#include <pthread.h>
int pthread_kill(pthread_t tid, int signal);
// Sends signal directly to specific thread

// Thread signal masks
#include <pthread.h>
int pthread_sigmask(int how, const sigset_t *set, sigset_t *oldset);
// Each thread has individual signal mask

14.5 Windows Alternative: APCs¶

Windows doesn't natively support UNIX-style signals. Uses Asynchronous Procedure Calls (APCs): - Specify callback function executing asynchronously in context of specific user thread - Delivered when thread enters alertable wait state - Key difference: APC delivered directly to particular thread, not process

14.6 Common POSIX/Linux Signals¶

Signal Number Description & Default Action
SIGINT 2 Terminal interrupt (<Ctrl>+<C>). Terminate.
SIGABRT 6 abort() called. Terminate with core dump.
SIGKILL 9 Uncatchable, unignorable immediate termination.
SIGSEGV 11 Segmentation fault (invalid memory). Core dump.
SIGALRM 14 alarm() timer expired. Terminate.
SIGSTOP 17/19/23 Uncatchable, unignorable pause.
SIGCONT 18/19/25 Resume stopped process.

14.7 Signal Handling API¶

Simple (Legacy)¶

#include <signal.h>
void (*signal(int sig, void (*handler)(int)))(int);

// Example
void handler(int sig) {
    printf("Caught signal %d\n", sig);
}
signal(SIGINT, handler);

Robust (Modern) — sigaction()¶

#include <signal.h>

struct sigaction sa;
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sa.sa_flags = 0;  // or SA_RESTART, SA_SIGINFO, etc.

sigaction(SIGINT, &sa, NULL);

Async-Signal-Safe Functions¶

Only these can be safely called from signal handlers: - write(), read(), open(), close() - fork(), exec(), exit(), _exit() - kill(), raise(), alarm() - sigaction(), sigprocmask(), sigpending() - NOT safe: printf(), malloc(), free(), pthread_mutex_lock(), etc.

14.8 Signal Mask Operations¶

#include <signal.h>

// Block signals
sigset_t set;
sigemptyset(&set);
sigaddset(&set, SIGINT);
sigprocmask(SIG_BLOCK, &set, NULL);

// Unblock
sigprocmask(SIG_UNBLOCK, &set, NULL);

// Check pending
sigpending(&set);

In Multithreaded Programs¶

#include <pthread.h>
#include <signal.h>

// Each thread has its own signal mask
pthread_sigmask(SIG_BLOCK, &set, NULL);  // Block in this thread only

14.9 Common Patterns¶

Timeout with alarm()¶

void timeout_handler(int sig) {
    // Handle timeout
}

signal(SIGALRM, timeout_handler);
alarm(5);  // SIGALRM in 5 seconds
// ... do work ...
alarm(0);  // Cancel

Ignoring Signals¶

signal(SIGPIPE, SIG_IGN);  // Ignore broken pipe (common in network code)

Restoring Default¶

signal(SIGINT, SIG_DFL);  // Restore default action

14.10 Signal vs Other IPC¶

Mechanism Scope Use Case
Signals Process/thread notification Async events, termination, timers
Pipes/FIFOs Byte stream Data transfer between processes
Sockets Bidirectional messages Local/remote communication
Shared Memory Shared data High-speed data sharing
Semaphores/Mutexes Synchronization Mutual exclusion, resource counting

14.11 Key Takeaways¶

  • Signals = software interrupts for async/sync event notification
  • Lifecycle: Generation → Delivery → Handling
  • Synchronous = internal fault (delivered to faulting thread)
  • Asynchronous = external event (delivered to process/any thread)
  • Cannot catch/block: SIGKILL, SIGSTOP
  • Multithreaded delivery: 4 strategies; thread-specific for sync signals
  • Handler safety: Only async-signal-safe functions allowed
  • Modern API: sigaction() > signal(); pthread_kill() for thread-targeted
  • Windows: Uses APCs instead of signals

14.12 Exam-Relevant MCQ Patterns¶

  • Q70: SIGKILL and SIGSTOP cannot be caught, blocked, or ignored
