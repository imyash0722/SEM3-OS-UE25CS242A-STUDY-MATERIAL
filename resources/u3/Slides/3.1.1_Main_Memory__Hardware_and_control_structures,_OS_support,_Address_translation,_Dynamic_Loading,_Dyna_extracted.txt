Logical vs. Physical Address Space
OPERATING SYSTEMS
The concept of a logical address space that is bound to a separate physical address space is central to proper memory management
Logical address – generated by the CPU; also referred to as virtual address
Physical address – address seen by the memory unit
Logical and physical addresses are the same in compile-time and load-time address-binding schemes; logical (virtual) and physical addresses differ in execution-time address-binding scheme
Logical address space is the set of all logical addresses generated by a program
Physical address space is the set of all physical addresses generated by a program

Routine is not loaded until it is called
Better memory-space utilization; unused routine is never loaded
All routines kept on disk in relocatable load format

Dynamic Linking
OPERATING SYSTEMS
Static linking – system libraries and program code combined by the loader into the binary program image
Dynamic linking –linking postponed until execution time
Small piece of code, stub, used to locate the appropriate memory-resident library routine
Stub replaces itself with the address of the routine, and executes the routine
Operating system checks if routine is in processes’ memory address
If not in address space, add to address space
Dynamic linking is particularly useful for libraries
Other programs linked before the new library was installed will continue using the older library
This System also known as shared libraries
Consider applicability to patching system libraries
Versioning may be needed
Static and Dynamic Linking
OPERATING SYSTEMS
A program whose necessary library functions are embedded directly in the program’s executable binary file is statically linked to its libraries
The main disadvantage of static linkage is that every program generated must contain copies of exactly the same common system library functions
Dynamic linking is more efficient in terms of both physical memory and disk-space usage because it loads the system libraries into memory only once


Memory-Mapped Files (mmap)
OPERATING SYSTEMS

Mapping file contents directly into the process virtual address space.Access disk files via memory pointers (ptr[i]) instead of standard I/O system calls.Eliminate data duplication between kernel buffers and user space.
How It Works:
Address Translation: OS allocates a virtual address range to the file without loading it into physical RAM.
OS Support & Page Faults: Reading an address triggers a hardware page fault; the OS then pages the disk content into Main Memory.
Dynamic Shared Libraries: Uses the same mechanism as shared libraries to allow multiple processes to share memory safely.
Two Core Modes
Shared Mapping (MAP_SHARED): Writes modify the actual file on disk and are instantly visible to other processes.
Private Mapping (MAP_PRIVATE): Utilizes Copy-on-Write (CoW); modifications stay in memory and never change the disk file.
Advantages
High Performance: Bypasses overhead from read() and write() system calls.
Zero-Copy I/O: Transfers data directly from disk cache to user space.
Efficient IPC: Enables lightning-fast Inter-Process Communication via shared physical pages.

1. First access:A demand-paging fault occurs; a page-sized chunk of the file is read from disk into a physical page.
2. Subsequent access:Reads and writes to the file are handled as ordinary memory accesses — no read()/write() system call overhead.
3. Deferred write-back:Modified pages aren't written to disk immediately; under memory pressure they're paged to swap space instead of being lost.
4. On close:All memory-mapped data is written back to secondary storage and unmapped from the process's virtual memory.
Solaris Example:
mmap(): File is mapped directly into the process's address space.
open() / read() / write(): File is still memory-mapped — but into kernel address space.
Net effect: All file I/O goes through the efficient memory subsystem, avoiding traditional system-call overhead.

Memory-Mapped Files: Advantages and Sharing Memory
OPERATING SYSTEMS
Faster file access 
The file can be accessed directly through memory addresses. 
This can be faster than repeatedly using read() and write() system calls. 
Less data copying 
The operating system can map file pages directly into the process's address space. 
This reduces unnecessary copying of data between kernel buffers and user-space buffers. 
Random access is easy 
Any part of the file can be accessed directly using an address. 
There is no need to sequentially read the file to reach a particular location. 
Efficient for large files 
The entire file does not necessarily need to be loaded into RAM. 
The OS loads required pages into memory when they are accessed using demand paging. 

Easy programming
After mapping, the file can be accessed using normal pointer/array operations. 
For example: 
data[100]
can access data at a particular location in the mapped file.
Sharing between processes 
Multiple processes can map the same file and potentially share the same physical memory pages. 
This can be useful for IPC and shared data. 
Changes can be reflected in the file 
With a shared mapping (MAP_SHARED), modifications to the mapped memory can be written back to the underlying file.
Memory-Mapped Files: Advantages and Sharing Memory
OPERATING SYSTEMS
Concurrent access, copy-on-write, and shared memory
Concurrent SharingMultiple processes can map the same file at once. Each process's virtual memory map points to the same physical page — the page holding the disk block — so writes by one process are immediately visible to all others.
Copy-on-WriteMapping calls can support copy-on-write: processes share a file read-only, but any process that modifies data gets its own private copy of just that data.
Shared Memory via mmap (diagram box)
Process A → Mapped File (shared region)
Process B → Mapped File (shared region)
Each communicating process memory-maps the same file (or POSIX shared-memory object) into its address space — the mapping itself becomes the shared-memory region for IPC.
Coordinating AccessSince the memory is shared, processes typically use a mutual-exclusion mechanism to coordinate access to the shared data.
