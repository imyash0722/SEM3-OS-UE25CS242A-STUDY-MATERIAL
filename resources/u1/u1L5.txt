Slide 4 & 5: Process Creation & Process Tree in Linux
--------------------------------------------------------------------------------
• Process Creation Overview:
  - A parent process creates children processes, which in turn can create other processes, forming a hierarchical tree of processes.
  - Each process is uniquely identified and managed by a Process Identifier (PID).

• Silberschatz Figure 3.7: Process Tree on a Modern Linux System:

                            [ systemd ]
                             (pid = 1)
                                 |
         +-----------------------+-----------------------+
         |                       |                       |
     [ logind ]              [ python ]               [ sshd ]
    (pid = 8415)            (pid = 2808)            (pid = 3028)
         |                                               |
      [ bash ]                                        [ sshd ]
    (pid = 8416)                                    (pid = 3610)
         |                                               |
     +---+---+                                        [ tcsh ]
     |       |                                      (pid = 4005)
   [ ps ]  [ vim ]
(pid=9298)(pid=9204)

• Resource Sharing Options:
  1. Parent and children share all resources.
  2. Children share a subset of the parent's resources (prevents resource overload).
  3. Parent and child share no resources (isolated execution).
• Execution Options:
  1. Parent and children execute concurrently.
  2. Parent waits until some or all of its children terminate.

Slide 6 & 7: Process Creation using fork() and exec()
--------------------------------------------------------------------------------
• Mechanics of fork() and exec():
  - `fork()`: Creates a new process. The child process is an exact copy of the parent's address space (data space, heap, stack, file descriptors).
  - `exec()`: Overwrites the process's memory space (text, data, heap, stack) with a completely new program from disk and begins execution at `main()`.

• Silberschatz Figure 3.8: Process Creation Sequence:

       PARENT PROCESS                              CHILD PROCESS
  +-----------------------+
  | Executes code         |
  | Calls fork() ---------+-------------------> +-------------------------+
  |                       |                     | Child process created   |
  | Checks pid:           |                     | Checks pid:             |
  |   pid > 0 (Child PID) |                     |   pid == 0              |
  | Calls wait()          |                     | Calls exec()            |
  |         |             |                     | (Overlays memory)       |
  |         v (Blocks)    |                     | Executes new program    |
  |         .             |                     | Calls exit()            |
  |         .             |<--------------------+                         |
  | Wakes up & resumes    |      Child terminates
  | Completes execution   |
  +-----------------------+

• Complete C Code Example (Slide 7):
  #include <stdio.h>
  #include <unistd.h>
  #include <sys/types.h>
  #include <sys/wait.h>

  int main() {
      pid_t pid;

      /* Fork a child process */
      pid = fork();

      if (pid < 0) {
          /* Error occurred */
          fprintf(stderr, "Fork Failed\n");
          return 1;
      }
      else if (pid == 0) {
          /* Child process: execute /bin/ls */
          execlp("/bin/ls", "ls", NULL);
      }
      else {
          /* Parent process: wait for child to complete */
          wait(NULL);
          printf("Child Complete\n");
      }

      return 0;
  }

Slide 8 & 9: Process Termination (Normal, Abnormal, Cascading, Zombies & Orphans)
--------------------------------------------------------------------------------
• Process Termination Mechanisms:
  - Normal: Process executes its final statement or explicitly calls `exit(status)`.
    * Kernel deallocates physical memory, file locks, open file descriptors.
    * Returns exit status data from child to parent (reaped via `wait()`).
  - Abnormal: Parent or OS terminates child using `abort()` or signals:
    * Child exceeds allocated resource limits (CPU time, memory quotas).
    * Task assigned to child is no longer required.
    * Parent exits in an operating system that prohibits orphan processes.

• Cascading Termination:
  - If a process terminates (normally or abnormally), some operating systems mandate that all its descendant children, grandchildren, etc. must also be terminated. Initiated by the kernel.

• Zombie vs. Orphan Processes:
  1. **Zombie Process**:
     - A process that has terminated via `exit()`, but whose parent has NOT yet invoked `wait()`.
     - Its entry in the process table remains to preserve its PID and exit status for the parent.
     - When parent calls `wait()`, the zombie is reaped and removed from the process table.
  2. **Orphan Process**:
     - A child process whose parent process terminated without waiting for it.
     - The operating system resolves this by re-parenting the orphan to `init` (or `systemd`, PID 1).
     - `init` / `systemd` periodically invokes `wait()` to collect exit statuses and reap orphaned children.

Slide 10: System Calls for Process Management - Process Identifiers
--------------------------------------------------------------------------------
• Properties of PIDs:
  - Every process is assigned a unique, non-negative integer identifier: Process ID (PID).
  - Used by system calls to target specific processes (signals, priority modification).
  - PIDs are finite and reused after processes terminate.
  - Modern Unix/Linux systems use delay-reuse algorithms to prevent race conditions where a newly created process accidentally receives the PID of a recently dead process.

Slide 11: The fork() System Call
--------------------------------------------------------------------------------
• Prototype:
  #include <unistd.h>
  pid_t fork(void);

• Return Value Characteristics:
  - In Child: Returns 0.
  - In Parent: Returns the PID of the newly created child process (> 0).
  - On Failure: Returns -1 (e.g. system process limit reached).
• Address Space Semantics:
  - The child is an exact copy of the parent's data segment, heap, and stack.
  - In modern OSs, Copy-on-Write (COW) is used: parent and child share physical pages read-only until one attempts to write, whereupon the page is duplicated.

--------------------------------------------------------------------------------
Slide 12: The exit() System Call & Termination Types
--------------------------------------------------------------------------------
• Five Normal Termination Paths:
  1. Executing `return` from `main()`.
  2. Calling the standard C library `exit()` function (flushes I/O buffers, calls registered `atexit` handlers).
  3. Calling the direct kernel system call `_exit()` or `_Exit()`.
  4. Executing a return from the initial start routine of the last thread in the process.
  5. Calling `pthread_exit()` from the last thread in the process.

• Three Abnormal Termination Paths:
  1. Calling `abort()` (generates `SIGABRT` signal).
  2. Receiving certain terminating signals from the OS or other processes (e.g., `SIGKILL`, `SIGSEGV`, `SIGFPE`).
  3. The last thread responds to a thread cancellation request.

Slide 13: The wait() and waitpid() System Calls
--------------------------------------------------------------------------------
• Prototypes:
  #include <sys/wait.h>
  pid_t wait(int *statloc);
  pid_t waitpid(pid_t pid, int *statloc, int options);

• Behavior of wait():
  - Blocks the caller if any child is actively running until one child terminates.
  - Returns immediately with termination status if a child has already terminated (zombie).
  - Returns -1 with `errno` set to `ECHILD` if the process has no children.
  - Receives `SIGCHLD` signal asynchronously upon child state change.
• Behavior of waitpid():
  - `pid > 0`: Wait for specific child whose PID equals `pid`.
  - `pid == -1`: Wait for any child process (identical to `wait()`).
  - `pid == 0`: Wait for any child in the same process group.
  - `pid < -1`: Wait for any child whose process group ID equals `|pid|`.
  - Options (e.g., `WNOHANG`): Non-blocking mode; returns 0 if status not available.

--------------------------------------------------------------------------------
Slide 14: The waitid() System Call
--------------------------------------------------------------------------------
• Prototype:
  #include <sys/wait.h>
  int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);

• Features:
  - Allows fine-grained specification of which child state change to wait for.
  - `idtype`: `P_PID` (specific PID), `P_PGID` (process group), `P_ALL` (all children).
  - Returns 0 on success, -1 on failure.

Slide 15: The exec() Family of Functions
--------------------------------------------------------------------------------
• Prototypes:
  #include <unistd.h>
  int execl(const char *pathname, const char *arg0, ... /*, (char *)0 */);
  int execv(const char *pathname, char *const argv[]);
  int execle(const char *pathname, const char *arg0, ... /*, (char *)0, char *const envp[] */);
  int execve(const char *pathname, char *const argv[], char *const envp[]);
  int execlp(const char *filename, const char *arg0, ... /*, (char *)0 */);
  int execvp(const char *filename, char *const argv[]);
  int fexecve(int fd, char *const argv[], char *const envp[]);

• Mnemonic Decoding:
  - `l` (List): Arguments are passed individually as variable arguments ending with `(char *)NULL`.
  - `v` (Vector): Arguments are passed as an array of pointers (`char *argv[]`).
  - `p` (Path): Takes a filename and searches through directories listed in the `PATH` environment variable.
  - `e` (Environment): Allows caller to pass custom environment variables via `char *const envp[]`.
  - `f` (File Descriptor): Executes file referenced by an open file descriptor.
  - Note: `execve()` is the true underlying Linux system call; all other `exec*` variants are C runtime wrapper library functions.

Slide 17: Race Conditions
--------------------------------------------------------------------------------
• Definition:
  - Occurs when multiple processes access and manipulate shared resources, and the execution outcome depends on the unpredictable order in which CPU scheduling occurs.
• Post-fork() Race:
  - After `fork()`, whether parent or child runs first depends purely on the OS scheduler.
  - Never write code that presumes parent runs first or child runs first.
• Flawed Polling Loop:
  while (getppid() != 1) {
      sleep(1);
  }
  - Inefficiently attempts to detect parent termination by checking if re-parented to `init`. Wastes CPU cycles and induces latency.

Slide 18: I/O Request Life Cycle (I/O-Bound Process)
--------------------------------------------------------------------------------
• Sequence of Events:
  1. Running: Process executes on the CPU until it issues an I/O system call (e.g. read/write).
  2. Blocked: OS transitions process to the Waiting / Blocked queue.
  3. Preemption: CPU is immediately reassigned to another ready process in the ready queue.
  4. Device Servicing: Device controller processes transfer asynchronously.
  5. Interrupt: Device signals completion via hardware interrupt to the CPU.
  6. Ready: OS interrupt handler moves process from Waiting queue back to Ready queue.
  7. Resume: Scheduler dispatches process back to CPU for brief computation before next I/O.
