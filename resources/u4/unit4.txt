File Concept
OPERATING SYSTEMS
●Computers can store information on various storage media, such as 
magnetic disks, magnetic tapes, and optical disks.
●File is logical storage where as disks are physical storage unit
●What is a File?
●Collection of related information
●Data cannot to be written to disk unless they are in files
●Data can be Numeric, alphabetic, alphanumeric, binary
●A file is a sequence of bits, bytes, lines, or records, the meaning of which is 
defined by the file’s creator and user
●Contents  of file can be source or executable programs, numeric or text data, 
photos, music, video, and so on.

●A device driver is a specialized software component that enables the 
Operating System (OS) to communicate with and control a hardware device.

●The OS does not need to understand the internal details of every hardware 
device.
●The driver provides a standard interface through which the OS can access 
the device.
Examples - Keyboard Driver, Mouse Driver, Printer Driver, Disk/Storage Driver,

--- [Slide / Page 6] ---
How Does a Device Driver Work? 
OPERATING SYSTEMS
Device Driver Workflow
1. Application Request - A user application requests an operation such as read, write, or print.
2. System Call - The application uses a system call to request the service from the OS.
3. Kernel Processing - The OS kernel receives the request and determines which device and driver are 
required.
4. Device Driver - The driver converts the OS request into device-specific commands.
5. Hardware Operation - The hardware performs the requested operation.
6. Interrupt / Response
○The device may generate an interrupt when the operation is completed.
○
The driver informs the OS, which then returns the result to the application.
Example
Application → read() → Kernel → Disk Driver → SSD/HDD → Interrupt → Kernel → Application

NAND Flash

Flash Organization
●Page: Basic unit for read/write operations.
●Block: Collection of pages; erase operation is performed at block level.

--- [Slide / Page 13] ---
Flash Storage Management 
OPERATING SYSTEMS
Why is Flash Storage Management Required?
Flash memory has limitations:
●A flash cell has a limited number of write/erase cycles.
●Data cannot be overwritten directly like a magnetic disk.
●Erasing is performed at the block level, while writing is performed at the 
page level.
UNIVERSITY

--- [Slide / Page 14] ---
Flash Storage Management 
OPERATING SYSTEMS
Key Management Techniques
1. Flash Translation Layer (FTL)
●
Maps logical addresses from the OS to physical locations in flash memory.
●
Hides the internal organization of flash from the OS.
2. Wear Leveling
●
Distributes write/erase operations across blocks.
●
Prevents some blocks from wearing out earlier than others.
3. Garbage Collection
●
Identifies blocks containing obsolete data.
●
Moves valid data and frees blocks for future writes.
4. Bad Block Management
●
Detects unusable flash blocks.
●
Prevents the system from storing data in damaged blocks.

Free-Space Management
OPERATING SYSTEMS
• Need to reuse the disk space from deleted files for new files
• To keep track of free disk space, the system maintains a free-space list
• The free-space list records all free disk blocks
• When a file is created, the free-space list is searched for the required amount of space 
and allocate that space to the new file. This space is then removed from the free-space 
list. 
• When a file is deleted, its disk space is added to the free-space list
UNIVERSITY

--- [Slide / Page 5] ---
Bit Vector 
OPERATING SYSTEMS
• The free-space list is implemented as a bit map or bit vector. 
• Each block is represented by 1 bit. 
• If the block is free, the bit is 1; if the block is allocated, the bit is 0
• For example, consider a disk where blocks 2, 3, 4, 5, 8, 9, 10, 11, 12, 13, 17, 18, 25, 26, 
and 27 are free and the rest of the blocks are allocated. 
• The free-space bit map would be 001111001111110001100000011100000 ...
• The main advantage of this approach is its relative simplicity and its efficiency in finding 
the first free block or n consecutive free blocks on the disk
UNIVERSITY

--- [Slide / Page 6] ---
Linked List 
OPERATING SYSTEMS
•
Link together all the free disk blocks, keeping a pointer to the first free 
block in a special location on the disk and caching it in memory.
•
The first free block contains a pointer to the next free disk block, and so on
•
Example: Consider blocks 2, 3, 4, 5, 8, 9, 10, 11, 12, 13, 17, 18, 25, 26, and 
27 are free and the rest of the blocks are allocated.
•
The pointer would point to block 2 as the first free block. Block 2 would 
contain a pointer to block 3, which would point to block 4 and so on
•
This scheme is not efficient; to traverse the list, one must read each block, 
which requires substantial I/O time.

Grouping 
OPERATING SYSTEMS
• A modification of the free-list approach stores the addresses of n free blocks 
in the first free block. 
• The first n−1 of these blocks are actually free. 
• The last block contains the addresses of another n free blocks, and so on. 
• The addresses of a large number of free blocks can now be found quickly, 
unlike the situation when the standard linked-list approach is used.
UNIVERSITY

--- [Slide / Page 9] ---
Counting 
OPERATING SYSTEMS
• Generally, several contiguous blocks may be allocated or freed simultaneously, 
particularly when space is allocated with the contiguous-allocation algorithm or 
through clustering.
• Rather than keeping a list of n free disk addresses, we can keep the address of the first 
free block and the number (n) of free contiguous blocks that follow the first block
• Each entry in the free-space list then consists of a disk address and a count.
• The entries can be stored in a balanced tree, rather than a linked list, for efficient 
lookup, insertion, and deletion.
UNIVERSITY

Efficiency and Performance
OPERATING SYSTEMS
Efficiency dependent on:
• Disk allocation and directory algorithms
• Types of data kept in file’s directory entry
• Pre-allocation or as-needed allocation of metadata structures
• Fixed-size or varying-size data structures
Performance dependent on:
• Keeping data and metadata close together
• Buffer cache – separate section of main memory for frequently used blocks
• Free-behind and read-ahead – techniques to optimize sequential access
• Reads frequently slower than writes
UNIVERSITY

--- [Slide / Page 11] ---
Page cache
OPERATING SYSTEMS
•
Some systems maintain a separate section of main memory for a buffer cache, where blocks are kept 
under the assumption that they will be used again shortly. 
•
Other systems cache file data using a page cache. The page cache uses virtual memory techniques to 
cache file data as pages rather than as file-system-oriented blocks. 
•
Caching file data using virtual addresses is far more efficient than caching through physical disk blocks, as 
accesses interface with virtual memory rather than the file system. 
•
Several systems—including Solaris, Linux, and Windows —use page caching to cache both process pages 
and file data. This is known as unified virtual memory.

Page replacement
OPERATING SYSTEMS
•
Sequential access can be optimized by techniques known as free-behind and read-ahead. 
•
Free-behind removes a page from the buffer as soon as the next page is requested. The 
previous pages are not likely to be used again and waste buffer space. 
•
With read-ahead, a requested page and several subsequent pages are read and cached. 
These pages are likely to be requested after the current page is processed. 
•
Retrieving these data from the disk in one transfer and caching them saves a considerable 
amount of time

Selecting a Disk-Scheduling Algorithm
OPERATING SYSTEMS
●SSTF is common and has a natural appeal
●SCAN and C-SCAN perform better for systems that place a heavy load on

●Less starvation
●Performance depends on the number and types of requests

--- [Slide / Page 21] ---
Selecting a Disk-Scheduling Algorithm (Cont.)
OPERATING SYSTEMS
●What about rotational latency?
●Difficult for OS to calculate
●The rotational latency can be nearly as large as the average seek time. 
●It is difficult for the operating system to schedule for improved rotational 
latency, though, because modern disks do not disclose the physical location 
of logical blocks. 
●Disk manufacturers have been alleviating this problem by implementing disk-
scheduling algorithms in the controller hardware built into the disk drive. 
●How does disk-based queueing effect OS queue ordering efforts?
●If the OS sends a batch of requests to the controller, the controller can queue them 
and then schedule them to improve both the seek time and the rotational latency.

○Files and data
○Memory and CPU
○Network resources
○User accounts and credentials
●A security breach can result in:
○Unauthorized access
○Data theft or disclosure
○Data modification or destruction
○Misuse of system resources
○Disruption of services

Types of Security Violations

3. Breach of Availability - Unauthorized destruction or disruption of resources.
4. Theft of Service - Unauthorized use of system resources.

Program Threats 
OPERATING SYSTEMS
●Program threats occur when a malicious or compromised program attempts to gain 
unauthorized access, misuse resources, or damage a computer system.
●Programs and processes are the primary means through which work is performed 
on a computer.
●An attacker can exploit a program to:
○Access unauthorized data
○Modify or delete files
○Gain additional privileges
○Execute malicious code
○Disrupt system operation

Malware and Trojan Horse 
OPERATING SYSTEMS
Malware - Malware (Malicious Software) is software designed to exploit, disable, 
damage, or gain unauthorized access to a computer system.
●Malware may perform malicious actions while appearing to be a legitimate 
program.
●Common forms include: Trojan Horse, Spyware, Ransomware, Viruses, Worms
Trojan Horse
●A Trojan Horse is a program that appears to perform a legitimate function but 
secretly performs malicious activities.
●It may run with the user's privileges, allowing it to access resources available to 
that user.
●The user may unknowingly install or execute the program.
UNIVERSITY

--- [Slide / Page 8] ---
Spyware
OPERATING SYSTEMS
Spyware
●Spyware is malicious software that secretly collects information about a user or 
system.
●It may monitor:
○Browsing activity
○User behavior
○Credentials and personal information
○Files and system information
●Collected information may be sent to a remote attacker/server without the user's 
knowledge.
Example: A malicious application secretly records user activity and sends the collected 
information to an attacker.
UNIVERSITY

--- [Slide / Page 9] ---
Ransomware 
OPERATING SYSTEMS
Ransomware
●Ransomware is malware that encrypts files or data on a system.
●The attacker demands a ransom payment in exchange for the decryption key.
●Without the key, the victim may be unable to access the encrypted data.
UNIVERSITY

--- [Slide / Page 10] ---
Code Injection 
OPERATING SYSTEMS
●Code injection is a security attack in which an attacker causes unauthorized code to be 
inserted into or executed by a program.
●It commonly occurs due to poor or insecure programming practices.
●If successful, the attacker may:
a. Modify program behavior
b. Execute unauthorized commands
c. Access protected data
d. Gain control over the program
Common Example: Buffer Overflow
●A program stores data in a fixed-size buffer.
●If more data is supplied than the buffer can hold, the extra data may overwrite nearby 
memory.
●Carefully crafted input can potentially alter program execution.
UNIVERSITY

Viruses 
OPERATING SYSTEMS
●A virus is a fragment of code embedded in a legitimate program or file.
●It is designed to replicate itself by infecting other programs or files.
●A virus generally requires user action or execution of an infected program to 
spread.
●Viruses can:
a. Modify or destroy files
b. Corrupt programs
c. Cause system crashes or malfunction
d. Spread to other files or systems
UNIVERSITY

Worms 
OPERATING SYSTEMS

systems, typically through a network.
●Unlike a virus, a worm does not need to attach itself to another program or 
file.
●Worms can spread automatically by exploiting network or software 
vulnerabilities.
●They may consume system and network resources and cause:
a. Network congestion
b. System slowdown
c. Service disruption
d. Installation of additional malware

OPERATING SYSTEMS

●It may be intentionally created during development or maliciously inserted by an

●If discovered and exploited, it can provide unauthorized access to system 
resources.
Principle of Least Privilege
●A user or program should be given only the minimum privileges required to 
perform its task.
●Privileges should be limited in:
○Scope — what resources can be accessed
○Time — how long access is required

Why is Implementation Needed?
●The Access Matrix provides a clear protection model, but a complete matrix can 
become very large.
●Most entries in the matrix are usually empty.
●Therefore, storing the entire matrix directly is not memory efficient.
●Operating systems use different techniques to implement the Access Matrix.
Common Implementations
1. Global Table
2. Access List for Objects (ACL)
3. Capability List

Implementation of the Access Matrix – Global table
OPERATING SYSTEMS
●A global table stores all non-empty access relationships in a single table.
●Each entry is represented as: <Domain, Object, Rights>
How It Works
1. A process requests access to an object.
2. The OS searches the global table.
3. It looks for the corresponding Domain–Object entry.
4. The requested operation is checked against the stored rights.
5. Access is allowed or denied.
Limitations
●Large table → inefficient use of memory
●Slow lookup → searching may take time
●Difficult to manage grouping of similar access rights

--- [Slide / Page 7] ---
Why Revocation of Access Rights is Needed 
OPERATING SYSTEMS
Revocation
●
Revocation means removing previously granted access rights from a user or domain.
●
It is necessary because access requirements can change over time.
●
Revocation is an important part of a dynamic protection system.
Why is Revocation Required?
●
A user's role or responsibility changes.
●
A user no longer needs access to a resource.
●
A resource becomes more restricted.
●
Temporary access has expired.
●
An administrator needs to withdraw previously granted permissions.
Simple Example
Before: D1 → File F1 → Read + Write
After Revocation: D1 → File F1 → Read : The Write right has been removed, while Read is retained.
UNIVERSITY

--- [Slide / Page 8] ---
Types of Revocation 
OPERATING SYSTEMS
Revocation can be classified based on when, how much, and for whom access is removed.
1. Immediate vs. Delayed
●
Immediate: Access is removed immediately.
●
Delayed: Revocation takes effect after a specified time or condition.
2. Selective vs. General
●
Selective: Remove access from a specific user/domain.
●
General: Remove access from all users/domains having that right.
3. Partial vs. Total
●
Partial: Remove some rights while keeping others.
●
Total: Remove all access rights to the object.
4. Temporary vs. Permanent
●
Temporary: Access is removed for a limited period or until a condition is met.
●
Permanent: Access is removed and does not automatically return.
UNIVERSITY

--- [Slide / Page 9] ---
Revocation Using ACL and Capability List 
OPERATING SYSTEMS
Revocation with Access Control List (ACL)
●In an ACL, each object maintains a list of domains/users and their access 
rights.
●To revoke access, the OS can remove or modify the corresponding entry.
●Therefore, revocation using ACL is relatively straightforward.
Revocation with Capability List
●In a Capability List, access rights are associated with domains.
●Capabilities may be distributed among different domains.
●Therefore, revoking a particular capability can be more difficult.
UNIVERSITY

--- [Slide / Page 10] ---
Revocation Techniques 
OPERATING SYSTEMS
When capabilities are distributed among domains, different techniques can be used to revoke access.
1. Reacquisition
●
Capabilities have a limited validity.
●
When they expire, the user/domain must request access again.
●
If access is revoked, the request is denied.
2. Back-Pointers
●
The system maintains pointers to all copies of a capability.
●
During revocation, these pointers are used to locate and modify/remove the capabilities.
3. Indirection
●
Access is managed through an intermediate/global table.
●
To revoke access, the corresponding entry in the table is deleted or invalidated.
4. Keys
●
A capability is associated with a key.
●
Changing or invalidating the key makes the old capability unusable.
