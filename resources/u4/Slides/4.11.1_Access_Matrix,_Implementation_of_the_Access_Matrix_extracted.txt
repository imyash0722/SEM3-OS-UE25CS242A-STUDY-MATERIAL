Access Matrix
OPERATING SYSTEMS
Protection Model
●The Access Matrix is a protection model used by an operating system to specify who can 
access what and what operations are permitted.
●It represents access permissions between:
○Domains → Subjects/users/processes
○Objects → Resources such as files, printers, memory, etc.
●Each cell contains the access rights allowed for a particular domain on an object.
Basic Structure
●Rows → Domains
●Columns → Objects
●Cells → Access Rights
Example Rights - read (r), write (w), execute (x), print, delete

Implementation of the Access Matrix
OPERATING SYSTEMS
Why is Implementation Needed?
●The Access Matrix provides a clear protection model, but a complete matrix can 
become very large.
●Most entries in the matrix are usually empty.
●Therefore, storing the entire matrix directly is not memory efficient.
●Operating systems use different techniques to implement the Access Matrix.
Common Implementations
1. Global Table
2. Access List for Objects (ACL)
3. Capability List

Implementation of the Access Matrix – Global table
OPERATING SYSTEMS
●A global table stores all non-empty access relationships in a single table.
●Each entry is represented as: <Domain, Object, Rights>
How It Works
1. A process requests access to an object.
2. The OS searches the global table.
3. It looks for the corresponding Domain–Object entry.
4. The requested operation is checked against the stored rights.
5. Access is allowed or denied.
Limitations
●Large table → inefficient use of memory
●Slow lookup → searching may take time
●Difficult to manage grouping of similar access rights

Implementation of the Access Matrix – Access list for objects
OPERATING SYSTEMS
●
In this approach, each object maintains a list of domains and their allowed rights.
●
The list answers: “Who can access this object, and what can they do?”
●
Format: Object → (Domain, Rights)
How it works
1. Process requests access to an object.
2. OS checks that object's access list.
3. It finds the requesting domain.
4. The requested operation is compared with the allowed rights.
5. Access is granted or denied.
Advantages
●
Easy to determine who can access an object.
●
Permissions can be easily modified.
●
Supports default permissions.
Limitation - Difficult to determine all objects accessible by a particular domain.

Capability List 
OPERATING SYSTEMS
●A capability list stores the access rights associated with a domain.
●It answers: “What objects can this domain access, and what can it do?”
●Format: Domain → (Object, Rights)
How it works
1. A process executes in a particular domain.
2. The OS checks that domain's capability list.
3. It finds the requested object.
4. The requested operation is checked against the stored rights.
5. Access is granted or denied.

Rights
