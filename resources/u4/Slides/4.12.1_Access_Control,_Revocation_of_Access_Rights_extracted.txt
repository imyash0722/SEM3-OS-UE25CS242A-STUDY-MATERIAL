OPERATING SYSTEMS

Why Revocation of Access Rights is Needed 
OPERATING SYSTEMS
Revocation
●
Revocation means removing previously granted access rights from a user or domain.
●
It is necessary because access requirements can change over time.
●
Revocation is an important part of a dynamic protection system.
Why is Revocation Required?
●
A user's role or responsibility changes.
●
A user no longer needs access to a resource.
●
A resource becomes more restricted.
●
Temporary access has expired.
●
An administrator needs to withdraw previously granted permissions.
Simple Example
Before: D1 → File F1 → Read + Write
After Revocation: D1 → File F1 → Read : The Write right has been removed, while Read is retained.

Types of Revocation 
OPERATING SYSTEMS
Revocation can be classified based on when, how much, and for whom access is removed.
1. Immediate vs. Delayed
●
Immediate: Access is removed immediately.
●
Delayed: Revocation takes effect after a specified time or condition.
2. Selective vs. General
●
Selective: Remove access from a specific user/domain.
●
General: Remove access from all users/domains having that right.
3. Partial vs. Total
●
Partial: Remove some rights while keeping others.
●
Total: Remove all access rights to the object.
4. Temporary vs. Permanent
●
Temporary: Access is removed for a limited period or until a condition is met.
●
Permanent: Access is removed and does not automatically return.

Revocation Using ACL and Capability List 
OPERATING SYSTEMS
Revocation with Access Control List (ACL)
●In an ACL, each object maintains a list of domains/users and their access 
rights.
●To revoke access, the OS can remove or modify the corresponding entry.
●Therefore, revocation using ACL is relatively straightforward.
Revocation with Capability List
●In a Capability List, access rights are associated with domains.
●Capabilities may be distributed among different domains.
●Therefore, revoking a particular capability can be more difficult.

--- Slide / Page 10 ---
Revocation Techniques 
OPERATING SYSTEMS
When capabilities are distributed among domains, different techniques can be used to revoke access.
1. Reacquisition
●
Capabilities have a limited validity.
●
When they expire, the user/domain must request access again.
●
If access is revoked, the request is denied.
2. Back-Pointers
●
The system maintains pointers to all copies of a capability.
●
During revocation, these pointers are used to locate and modify/remove the capabilities.
3. Indirection
●
Access is managed through an intermediate/global table.
●
To revoke access, the corresponding entry in the table is deleted or invalidated.
4. Keys
●
A capability is associated with a key.
●
Changing or invalidating the key makes the old capability unusable.

Role based access control
OPERATING SYSTEMS
•
Access permissions are assigned to roles, not directly to users
•
A role represents a job/function (e.g., Admin, Faculty, Student)
How it works:
●Users → assigned to roles
●Roles → assigned permissions
●Users gain access through roles
Example:
●Admin → read, write, delete
●Faculty → read, write
●Student → read only
If a user is assigned “Faculty” role → gets those permissions

Role based access control
OPERATING SYSTEMS
Advantages:
●Reduces complexity in access management
●Easy to update permissions (change role, not every user)
●Improves security (no direct permission assignment)
●Supports large systems efficiently
Limitation:
●Requires proper role design
●Too many roles → becomes complex
