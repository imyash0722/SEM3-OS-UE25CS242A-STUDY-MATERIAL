Unit 1 Process Management & CPU Scheduling (35 MCQs)

1. Ultra-Short Pointers: System Calls & Process Lifecycle

fork() Return Value: Returns 0 in the child process, the child's PID > 0 in the parent process, and -1 on failure. Parent and child receive duplicate but strictly independent address spaces.
vfork() Memory Sharing: vfork() suspends the parent and shares the parent's address space with the child until the child calls _exit() or exec*(). Variable mutations in the child directly alter the parent's variables!
wait(&status) & WEXITSTATUS: wait(&status) blocks the parent until a child terminates. WEXITSTATUS(status) extracts the child's lowest 8-bit return code (0–255).
Orphan vs Zombie:
• Orphan: Parent terminates while child continues running. Child is adopted by init / systemd (PID 1).
• Zombie (<defunct>): Child terminates, but parent has not yet called wait(). Child's entry remains in process table.
exec* Family: Overwrites the calling process image (code, data, heap, stack) with a new binary while preserving the same PID. Does not return on success.
Process States: New, Ready, Running, Waiting (Blocked), Terminated. The Dispatcher moves a process from Ready to Running (performing context switch and loading PC).
Dual-Mode & Traps: User mode = bit 1, Kernel mode = bit 0. A trap is a software-generated interrupt caused by an error (e.g. division by zero) or system call, switching mode securely to 0.
CPU Scheduling Formulas:
• $\text{Turnaround Time (TAT)} = \text{Completion Time (CT)} - \text{Arrival Time (AT)}$
• $\text{Waiting Time (WT)} = \text{Turnaround Time (TAT)} - \text{Burst Time (BT)}$
• $\text{Response Time (RT)} = \text{First CPU Allocation} - \text{Arrival Time (AT)}$

Unit 2 Threads, Synchronization & Deadlocks (35 MCQs)

1. Ultra-Short Pointers: Threads, IPC & Synchronization

Process vs Thread: Threads within the same process share the code section, data section, heap, and open files, but each thread has its own Thread ID, Program Counter (PC), Register set, and Stack.
Multithreading Models:
• Many-to-One: Multiple user threads mapped to 1 kernel thread. Fast switching, but one blocking system call halts the entire process; no multicore parallelism.
• One-to-One (Linux): Each user thread maps to a kernel thread. True multicore parallelism; kernel thread creation overhead.
• Many-to-Many: Multiplexes many user threads to an equal or smaller number of kernel threads.
Amdahl's Law Formula: $\text{Speedup} \le \frac{1}{S + \frac{1-S}{N}}$. If serial fraction $S = 0.20$ (20%), then on 4 cores ($N=4$): $\text{Speedup} = \frac{1}{0.20 + 0.80/4} = 2.5\times$. Max theoretical speedup as $N \to \infty$ is $1 / 0.20 = 5\times$.
Ordinary Pipes (demo_pipe.c): pipe(fd) yields fd[0] (read) and fd[1] (write). Half-duplex (unidirectional). Shared ancestry required. For parent-to-child flow: parent closes fd[0], child closes fd[1].
Named Pipes / FIFOs (fifo_read.c/write.c): Created with mkfifo(). Appears as a directory entry in the filesystem. Persists after process exits; allows communication between unrelated processes.
Shared Memory vs Message Passing: Shared memory is the fastest IPC because processes read/write RAM directly with zero kernel system call intervention after setup. Message passing involves kernel system call overhead for every message.
Critical Section Problem (3 Requirements): 1. Mutual Exclusion (only 1 inside CS), 2. Progress (selection cannot be postponed indefinitely), 3. Bounded Waiting (bound on times others can enter before request granted).
Mutex vs Counting Semaphore: Mutex has ownership (only the locking thread can unlock it). Semaphore has no ownership (any thread can call sem_post()).
Spinlocks: Busy-waiting locks. Optimal on multiprocessors for very short critical sections because they avoid the CPU latency of two context switches.

1. Ultra-Short Pointers: Memory, Paging, Page Replacement

Base & Limit Registers: Base = starting physical address; Limit = range/size of logical address space. Legal condition: $0 \le \text{Logical Address} < \text{Limit}$. Physical address = $\text{Base} + \text{Logical Address}$. If $\text{Logical} \ge \text{Limit} \implies$ Hardware Trap (Addressing/Segmentation fault).
Contiguous Allocation Strategies:
• First Fit: Allocate first hole that is big enough (fastest).
• Best Fit: Allocate smallest hole that is big enough (leaves smallest leftover hole).
• Worst Fit: Allocate largest hole (leaves largest leftover hole; worst utilization).
Fragmentation:
• External: Total memory exists to satisfy request, but is non-contiguous (solved by compaction or paging). 50% rule: $0.5N$ blocks lost.
• Internal: Allocated block is slightly larger than requested (paging has internal fragmentation on last page, average $0.5 \times \text{page size}$).
Paging Structure: Logical address split into Page Number ($p$) and Offset ($d$). Physical address = Frame Number ($f$) + Offset ($d$). Frame size = Page size ($2^d$ bytes). Paging completely eliminates external fragmentation.
Page Table Size: Number of entries = $2^{\text{address bits} - \text{offset bits}}$. Size = $\text{Entries} \times \text{PTE size}$. For 32-bit address, 4KB page ($d=12$), 4-byte PTE: $2^{20} \times 4\text{ B} = 4\text{ MB}$ per process.
Two-Level Paging: 32-bit address with 4KB page ($12$ bits offset): $p_1$ (10 bits) + $p_2$ (10 bits) + $d$ (12 bits). Without TLB, 1 memory access requires 3 physical memory accesses (outer table, inner table, data frame).
TLB Effective Access Time (EAT): $\text{EAT} = \alpha \times (t_{\text{TLB}} + t_{\text{RAM}}) + (1-\alpha) \times (t_{\text{TLB}} + 2 \times t_{\text{RAM}})$ where $\alpha$ is TLB hit ratio.
Copy-on-Write (COW): fork() shares pages read-only. When parent or child attempts to write, a page-protection trap occurs; OS copies only that page to a new frame and marks it read-write.
Minor vs Major Page Fault: Minor fault = page is already in RAM (shared library, free list, COW copy) with zero disk I/O. Major fault = page must be read from disk (high latency).
Dirty Bit (Modify Bit): Indicates if page was written to. If clean (0), overwrite immediately on page replacement. If dirty (1), must write back to disk before replacement (doubles fault time).
Belady's Anomaly (FIFO): Increasing the number of frame allocations causes the number of page faults to increase! (e.g., string 1,2,3,4,1,2,5,1,2,3,4,5: 3 frames = 9 faults, 4 frames = 10 faults).
Stack Algorithms (LRU & Optimal): The set of pages in memory for $n$ frames is always a subset of pages for $n+1$ frames. Therefore, LRU and Optimal never suffer from Belady's Anomaly.
Clock Algorithm (Second Chance): Circular queue of frames with a 1-bit reference bit. On fault: if bit is 0, replace frame; if bit is 1, clear bit to 0, advance clock hand, and continue searching.
Thrashing: High paging activity where CPU spends more time swapping than executing. Occurs when $\sum \text{WSS}_i > \text{Total Physical Memory}$. Prevented via Working Set Model or Page Fault Frequency (PFF).
