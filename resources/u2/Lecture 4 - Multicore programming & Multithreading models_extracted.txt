Multicore Programming

• Multicore, and multithreaded programming provides a mechanism for more 
efficient use of these multiple computing cores and improved concurrency.
• On a system with a single computing core, concurrency merely means that the 
execution of the threads will be interleaved over time , because the 
processing core is capable of executing only one thread at a time. 
• On a system with multiple cores, however, concurrency  means that some 
threads can run in parallel, because the system can assign a separate 
thread to each core

OPERATING SYSTEMS
five areas present challenges in programming for multicore systems: 
Identifying tasks- tasks are independent of one another and thus can run
    in parallel on individual cores.
Balance-programmers must also ensure that the tasks perform equal work of equal value
Data splitting- applications are divided into separate tasks, the data accessed 
     and manipulated by the tasks must be divided to run on separate cores. 
Data dependency- When one task depends on data from another, programmers must 
     ensure that the execution of the tasks is synchronized to accommodate the data dependency.
Testing and debugging- Testing and debugging concurrent programs is 
inherently more difficult than testing and debugging single-threaded applications.

●Types of Parallelism 
●In general, there are two types of parallelism: data parallelism and task 
parallelism. 
●Data parallelism focuses on distributing subsets of the same data across 
multiple computing cores and performing the same operation on each core.
●Task parallelism involves distributing not data but tasks (threads) across 
multiple computing cores. 
●Each thread is performing a unique operation. Different threads may be 
operating on the same data, or they may be operating on different data.

Pthreads: Thread Creation
●pthread_create: This is the primary function used to spawn a new flow of execution. 
Requires a function pointer (the "runner") for start routine.
         
        int pthread_create(pthread_t *thread, const pthread_attr_t *attr, void *(*start_routine) (void *), void *arg);
•
thread: A pointer to a pthread_t variable. This serves as the "handle" or ID for the thread once it is created.
•
attr: A pointer to an attribute structure. 
•
start_routine: This is a function pointer. It points to the function the thread should execute. This function 
must take a void * as an argument and return a void *.
•
arg: The data you want to pass to the thread. Since it is a void *, you can pass a pointer to a primitive, a 
struct, or an array.
• Common mistake: passing a local variable's address to pthread_create.
• If the creating function returns before the thread starts, that local variable's address (on the stack) 
becomes invalid.
• The Solution: Always pass data that is either Global, on the Heap (using malloc), or in the main 
function stack which is guaranteed to exist for the duration of the program.

Pthreads: Synchronizing Execution
●In a multithreaded program, the main thread often needs to wait for its worker 
threads to finish their tasks before it can aggregate results or exit.
int pthread_join(pthread_t thread, void **retval);
• retval: Allows the caller to receive a return value from the thread that just finished.
• This function is blocking. If the target thread is still running, the caller (usually the main 
thread) will sleep until the target thread terminates.
• Cleanup: Joining is essential. If a thread is not "detached" and not "joined," it can 
become a Zombie Thread, consuming system resources even after it has finished its 
work.

Pthreads: Explicit Termination
●While a thread normally exit when its "runner" function finishes, you can 
terminate it prematurely using pthread_exit.
void pthread_exit(void *retval);
• Note: If you call this in the main() thread, the process will stay alive until all other 
threads have finished. 
• If you simply call exit() or return from main(), the entire process including all its threads 
will be killed immediately.

Thread Scheduling
●Many-to-one and many-to-many models, thread library schedules user-level 
threads to run on CPU through kernel.
●Known as process-contention scope (PCS) since scheduling competition is 
within the process.
●Typically done via priority set by programmer.
●Kernel thread scheduled onto available CPU is system-contention scope (SCS) – 
competition among all threads in system
OPERATING SYSTEMS
Pthread Scheduling
●API allows specifying either PCS or SCS during thread creation
●PTHREAD_SCOPE_PROCESS schedules threads using PCS scheduling
●PTHREAD_SCOPE_SYSTEM schedules threads using SCS scheduling
●Can be limited by OS – Linux and Mac OS X only allow 
PTHREAD_SCOPE_SYSTEM

Pthread Scheduling API
#include <pthread.h> 
#include <stdio.h> 
#define NUM_THREADS 5 
int main(int argc, char *argv[]) { 
   int i, scope;
   pthread_t tid[NUM THREADS]; 
   pthread_attr_t attr; 
   /* get the default attributes */ 
   pthread_attr_init(&attr); 
   /* first inquire on the current scope */
   if (pthread_attr_getscope(&attr, &scope) != 0) 
      fprintf(stderr, "Unable to get scheduling scope\n"); 
   else { 
      if (scope == PTHREAD_SCOPE_PROCESS) 
         printf("PTHREAD_SCOPE_PROCESS"); 
      else if (scope == PTHREAD_SCOPE_SYSTEM) 
         printf("PTHREAD_SCOPE_SYSTEM"); 
      else
         fprintf(stderr, "Illegal scope value.\n"); 
   }

Advanced Thread Management
• Thread Pools: Creating threads is faster than processes, but doing it thousands of 
times for small tasks is still wasteful. 
• A Thread Pool creates a fixed number of threads at startup that "sit and wait" for 
work, preventing resource exhaustion.
• Thread Cancellation: Terminating a thread before it finishes.
• Asynchronous: Terminate immediately (Dangerous! Might leave a Mutex locked).
• Deferred: The thread periodically checks if it should exit (Safer).
