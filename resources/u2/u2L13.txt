Slide 4 & 5: Signal Fundamentals & Signal Classification
--------------------------------------------------------------------------------
• Definition:
  - A signal is a software interrupt mechanism used in UNIX-like systems to notify a process or thread that a specific asynchronous or synchronous event has occurred.
• Universal Signal Lifecycle:
  1. **Generation**: A hardware exception, kernel event, timer, or user action triggers signal generation.
  2. **Delivery**: The operating system kernel marks the signal as pending and delivers it to the target process or thread.
  3. **Handling**: Once delivered, the process executes the designated signal action (default action or user-defined handler).

• Classification: Synchronous vs. Asynchronous Signals:
  1. **Synchronous Signals**:
     - Generated by an internal operation directly executed by the running program.
     - Examples: Illegal memory access (`SIGSEGV`), integer division by zero (`SIGFPE`), illegal machine instruction (`SIGILL`).
     - Delivered strictly to the identical thread whose instruction triggered the event.
  2. **Asynchronous Signals**:
     - Generated by an event external to the executing thread.
     - Examples: User terminal keystrokes (pressing `<Ctrl>+<C>` -> `SIGINT`), hardware timer expiration (`SIGALRM`), child process termination (`SIGCHLD`), or an explicit signal sent by another process.
     - Delivered to another process or asynchronously to any thread capable of receiving it.

Slide 6: Signal Handlers
--------------------------------------------------------------------------------
• Two Types of Signal Handlers:
  1. **Default Signal Handler**:
     - Provided by the kernel for every signal.
     - Default actions include:
       * Terminate: Halts process execution immediately.
       * Core Dump: Halts process and generates a core memory image for debugging.
       * Ignore: Discards the signal without taking any action (e.g., `SIGCHLD` by default).
       * Stop: Suspends the process execution state.
       * Continue: Resumes execution of a previously stopped process.
  2. **User-Defined Signal Handler**:
     - A custom C function registered by the programmer (via `signal()` or `sigaction()`) that overrides the default action.
     - When the signal is delivered, the normal thread execution context is paused, the signal handler executes, and execution resumes where it left off.
  - **Critical Exception**:
    * `SIGKILL` (Forceful termination) and `SIGSTOP` (Forceful suspension) CANNOT be caught, blocked, or ignored by any user-defined handler!

Slide 7, 8 & 9: Signal Handling in Multithreaded Programs
--------------------------------------------------------------------------------
• Multithreaded Delivery Problem:
  - In a single-threaded program, signals are unambiguously delivered to the process.
  - In a multithreaded process with multiple concurrent threads, which thread receives the signal?
• The Four Delivery Strategies:
  1. Deliver the signal to the thread to which the signal specifically applies (mandatory for synchronous exceptions like `SIGSEGV` or `SIGFPE`).
  2. Deliver the signal to every thread in the process (e.g. process termination signals like `SIGINT`).
  3. Deliver the signal to certain threads in the process (threads that do not currently have the signal blocked).
  4. Assign a dedicated thread to receive all signals for the process (using `sigwait()`).

• Standard System Calls for Signal Dispatch:
  1. Process-Targeted Dispatch:
     #include <signal.h>
     int kill(pid_t pid, int signal);
     - Sends `signal` to the process identified by `pid`. The kernel decides which non-blocking thread within the process receives the signal.
  2. Thread-Targeted Dispatch (POSIX Pthreads):
     #include <signal.h>
     #include <pthread.h>
     int pthread_kill(pthread_t tid, int signal);
     - Sends `signal` directly to a specific individual thread handle `tid`.

• Signal Masks in Threads:
  - Each thread maintains an individual signal mask (set of blocked signals) using `pthread_sigmask()`.
  - If a signal is generated for the process, the kernel delivers it to the first thread found that does not block that signal.

Slide 10: Signals in Windows (Asynchronous Procedure Calls - APCs)
--------------------------------------------------------------------------------
• Windows Architecture:
  - Windows does not natively support UNIX-style signals.
  - Instead, it emulates signal functionality using **Asynchronous Procedure Calls (APCs)**.
• Mechanism:
  - The APC facility allows an application to specify a callback function that executes asynchronously in the context of a specific user thread when that thread enters an alertable wait state.
  - Key difference: An APC is delivered directly to a particular thread rather than to a process.

Slide 11: Common POSIX / Linux Signals Reference
--------------------------------------------------------------------------------
+-----------+---------------+-----------------------------------------------------------------------+
| Signal    | Signal Number | Description & Default Action                                          |
+-----------+---------------+-----------------------------------------------------------------------+
| SIGINT    | 2             | Terminal Interrupt: Sent when user types <Ctrl>+<C>. Terminate.       |
| SIGABRT   | 6             | Abort: Generated by abort() function. Terminate with core dump.       |
| SIGKILL   | 9             | Kill: Immediate uncatchable, unignorable termination.                 |
| SIGSEGV   | 11            | Segmentation Fault: Invalid memory reference / dereference. Dump.     |
| SIGALRM   | 14            | Alarm Clock: Timer set by alarm() system call expires. Terminate.     |
| SIGSTOP   | 17 / 19 / 23  | Stop: Pauses process execution. Uncatchable, unignorable.             |
| SIGCONT   | 18 / 19 / 25  | Continue: Resumes a paused/stopped process.                           |
